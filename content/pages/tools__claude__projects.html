Projects as reusable setups

A Project is a container for context. Used properly it's the difference between a good afternoon and a changed process.

Reviewed September 2026. This page names fast-moving vendor detail, so it carries a review date.

What goes in one

  • Instructions: who you are, who reads this, the standing rules, the refusals.
  • Examples: three past documents of the type you want produced.
  • Reference material: the style guide, the checklist, the scope inclusions.
  • The boundary: what this Project must never produce.

One per document type, not one per client

The common mistake is a Project per client, which multiplies maintenance and puts identifiable material in a container that gets shared. A Project per document type — vendor report, progress report, quote, scope letter — stays maintainable and keeps client detail out.

Keeping it current

  • One named owner per Project.
  • A quarterly read against a recent real document.
  • Examples replaced when the house style moves, not added to indefinitely.
